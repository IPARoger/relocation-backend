## Requirement: favorite place storage

Favorite places should reliably store:

- name (label)
- latitude
- longitude

(Current Web2 favorites already persist `place_id → places.latitude/longitude`
and `favorite_places.label`. This entry records the intended product contract so
future custom-location work does not regress it.)

## Requirement: custom (raw map-point) locations

When a user favorites an arbitrary map point (no named city), support:

- autogenerated suggested label (e.g. nearest-city / region heuristic)
- user-editable label
- optional note captured at save time

Example labels:

- "Colorado Mountains near Boulder"
- "Africa Wilderness"

## Current truth (for context only)

- Raw right-click favorites currently surface as the generic "Custom location"
  label.
- Screen 4 / View Chart and Comparison columns require a resolvable
  `place_id → lat/lon`; raw points without a stored place resolve to an honest
  blocked state by design.
